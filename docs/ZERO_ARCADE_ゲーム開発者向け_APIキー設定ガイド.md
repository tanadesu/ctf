# ZERO ARCADE ゲーム開発者向け：導入手順ガイド

この文書は、ゲームの開発者または開発者が使うAIにそのまま渡すための説明書です。APIや環境変数に詳しくなくても作業を始められるよう、順番に説明します。

## 最初に知っておくこと

ZERO ARCADEのAPIは、ゲームサーバーから「このプレイの結果」を受け取り、ユニコイン獲得用QR画像を返します。QRはURLではなく、アプリのウォレットにある「スキャン」で読み取る専用データです。

**今の3ゲームは、APIキーを入力するだけではまだ動きません。** ゲーム結果画面からAPIを呼び、返ってきた枚数とQRを画面に出す処理がまだないため、最初にゲームのコード変更が必要です。特に、キーを安全に置くサーバー側の処理も追加します。改修が完成した後は、ゲームのサーバー設定画面にAPIキーとAPI URLを登録すれば接続できます。

## ゲーム開発者に渡すもの

ゲーム開発者には、このガイドと[3ゲーム別の実装指示書](ZERO_ARCADE_3ゲーム別_AI実装指示書.md)、担当するゲームのGitHubリポジトリを渡してください。AIに実装を頼む場合は、下の「AIにそのまま渡す依頼文」を使えます。

開発者には、変更したコードをGitHubへ反映し、テスト結果と、どの画面・どのサーバー設定を使えばよいかを説明してもらってください。APIキーはGitHubのIssue、ソースコード、チャット、画面キャプチャに貼らず、実装完了後にサーバーの秘密設定へ登録します。

## 運営側で先に行うこと

1. adminの「ユニコイン」→「ZERO ARCADE連携」を開きます。
2. 「キーを作成」を押し、ゲーム名を入れ、付与方式を選んでキーを発行します。ctfは「勝敗で付与」、hanbaiとlocketは「千単位に四捨五入」です。
3. 発行直後に表示されるゲームIDとAPIキーを安全な場所へ一時保存してください。APIキーは画面を閉じると再表示できません。ゲームIDは参考情報で、API呼び出しには不要です。
4. ゲームのカードで「設定を編集」を開きます。
   - ctf：勝ち `10000`、負け `0`、引き分けは先方の回答まで空欄、上限 `10000`。
   - hanbai：上限 `10000`。
   - locket：上限 `10000`。
5. 「API発行を有効にする」にチェックし、「設定を保存」を押します。ctfは引き分け枚数が未設定でも勝敗結果は発行できます。同点では `422` となりQRを発行しません。
6. APIキーをそのゲームの担当開発者へ安全な方法で渡します。3ゲームで同じキーを使い回さないでください。紛失・漏えいした場合は再発行してください。再発行すると前のキーと未受取QRが無効になります。
7. admin本番サイトのホスト名を控えます。開発者へ渡すAPI URLは次の形です：

```text
https://<admin本番サイトのホスト名>/api/arcade/rewards
```

`<` `>` を含めず、実際のadminサイトのURLに置き換えてください。APIキーはゲームごとに違いますが、このAPI URLは3ゲーム共通です。

## 各ゲームが送るスコア

ゲーム側ではユニコイン数に換算せず、ゲームの結果値を送ってください。ユニコイン数の計算はadmin APIが行います。

| ゲーム | APIへ送る `points` | 追加値 | 結果から付与される枚数 |
| --- | --- | --- | --- |
| ctf | 本人のサーバー側スコア | 相手のサーバー側スコアを `opponentPoints` に送信 | 勝ち10,000、負け0、引き分けは未設定の間は発行なし |
| hanbai | 利益を切り捨てて整数にした数。負の利益は0 | なし | 利益を千単位に四捨五入。例：2,499→2,000枚、2,500→3,000枚 |
| locket | 画面に表示するPOWERを整数にした数 | なし | POWERを千単位に四捨五入。現行コードでは最大約10,000枚 |

## AIにそのまま渡す依頼文

担当ゲームのGitHubリポジトリを開いた状態で、以下をコピーしてAIに送ってください。`<ゲーム名>` を `ctf`、`hanbai`、`locket` のいずれかに置き換えます。APIキーそのものはAIへの依頼文に含めないでください。

```text
このリポジトリのゲーム「<ゲーム名>」に、ZERO ARCADEのユニコイン獲得QR連携を実装してください。

まずリポジトリのREADMEと現在のコードを確認し、docs/ZERO_ARCADE_3ゲーム別_AI実装指示書.md にある該当ゲームの指示、ならびにdocs/ZERO_ARCADE_ゲーム開発者向け_APIキー設定ガイド.mdを読んでください。ファイルがこのリポジトリにない場合は、私から別途共有した同名資料の内容に従ってください。現在のブランチの実装と資料に違いがあれば、最新のコードを優先し、違いと対応を報告してください。

API送信先は ZERO_ARCADE_API_URL、キーは ZERO_ARCADE_API_KEY というサーバー側の秘密環境変数から読み込んでください。キーをブラウザ用JavaScript、HTML、公開設定、ログ、Git履歴に含めないでください。ブラウザからadmin APIへ直接送信しないでください。

ゲーム終了時にサーバー側で確定した結果を https://<運営から渡されるadminホスト>/api/arcade/rewards へPOSTし、応答のcoinsとqrImageDataUrlを本人の結果画面に表示してください。QRデータはURLに変換しないでください。0枚ならQR画像を表示しないでください。同じプレイの再試行では同じplayIdとスコアを使い、重複発行を防いでください。API障害やQR発行エラーがあっても、ゲーム結果そのものは表示してください。

ゲーム固有の送信値、終了条件、変更ファイル、ctfの2人分の処理、hanbai/locketで必要なサーバー側中継、配信環境に応じたAPIルートの実装方法は、共有した3ゲーム別指示書の該当節に合わせてください。hanbaiとlocketは結果がブラウザ計算なので、単にブラウザの値を転送するだけで不正を完全防止できない点も明記してください。locketは本番がVercelの静的配信なら、その構成でAPIルートを動かせるよう設定してください。

作業後、変更したファイル、ローカルでの起動・確認方法、ホスティング先で秘密環境変数を設定する画面と項目名、デプロイ手順、正常時に結果画面へ出る内容、未確認事項を初心者にも分かる日本語で説明してください。APIキーの値は聞かず、コード・ログ・回答に出さないでください。
```

AIがadminホストを尋ねたら、運営から受け取った本番URLを伝えてください。**APIキーはコード変更やレビューが終わるまで渡す必要はありません。** 最終的に実際のキーを登録するのは、ホスティング先の秘密環境変数の設定画面です。

## 開発後にサーバーへ設定する値

ゲーム側の改修ができたら、ゲームを公開しているホスティングサービスの「Environment Variables」「環境変数」「Secrets」などの画面を開き、次の2項目を追加します。項目名は必ずこの通りにします。値は運営から受け取ったものを設定します。

| 名前 | 値 |
| --- | --- |
| `ZERO_ARCADE_API_URL` | `https://<admin本番ホスト>/api/arcade/rewards` |
| `ZERO_ARCADE_API_KEY` | そのゲーム用に発行された64桁のキー |

ローカル開発で `.env` ファイルが必要な場合は、ファイルをGitHubへ上げないよう `.gitignore` を確認します。APIキーを含む `.env` はソースコードと一緒に共有しません。ホスティング先へ設定を追加・変更した後は、サービスによって再デプロイまたは再起動が必要です。開発者に、設定後の再起動方法も確認してください。

ctfのリポジトリにはRender設定があります。Renderで動かしている場合はRenderのサービス画面にあるEnvironmentで設定します。locketは現在Vercelの静的配信設定です。Vercelで動かす場合はAPI処理もVercel上のサーバー機能として実装し、VercelのEnvironment Variablesに設定する必要があります。hanbaiの本番ホスティング先はこの資料からは分からないため、開発者に確認してください。ブラウザだけの静的配信では秘密キーを保護できず、連携APIも安全に呼べません。

## APIの動きと表示内容

ゲームサーバーは次の形式でAPIを呼びます。ctfの場合だけ `opponentPoints` も付けます。

```http
POST https://<admin本番ホスト>/api/arcade/rewards
Authorization: Bearer <そのゲームのAPIキー>
Content-Type: application/json

{"playId":"game-session-123","points":2500}
```

成功すると、APIは付与枚数とQR画像データを返します。結果画面には応答の `coins` と `qrImageDataUrl` を使ってください。固定の枚数やサンプルQRを画面に埋め込んではいけません。

```json
{
  "coins": 3000,
  "qrPayload": "ZERO1COIN:<64桁のコード>",
  "qrImageDataUrl": "data:image/png;base64,...",
  "expiresAt": 1790000000
}
```

QRは発行から24時間有効で、1人が1回だけ受け取れます。利用者はZERO ARCADEのウォレットを開き、「スキャン」からQRを読み込みます。通常のカメラアプリではURLとして開けません。

## 開発者から受け取る完了報告

次の項目がそろったら、管理された会場端末などで実機確認を行います。

1. 変更を反映したGitHubブランチまたはコミット。
2. どのホスティング先でゲームを動かしているか。
3. `ZERO_ARCADE_API_URL` と `ZERO_ARCADE_API_KEY` をどの秘密設定画面へ入れるか。キーの値を報告文に書かないこと。
4. 正常にゲームを終了したとき、結果画面に付与枚数とQRが出ること。
5. 同じ結果画面の再読み込み・再試行で同じQRになること。
6. API停止・キー未設定・0枚・引き分け未設定時に、ゲーム結果が消えず、状況が画面に分かること。
7. ZERO ARCADEアプリのスキャナーでQRを読み取り、残高が一度だけ増えること。

## よくあるエラー

| 表示・状態 | 確認すること |
| --- | --- |
| `401` | サーバーのAPIキーが正しいか。前のキーを再発行後も使っていないか。 |
| `403` | admin側でそのゲームのAPI発行が有効か。 |
| `400` | `playId` が1〜100文字か、スコアが整数か。ctfは `opponentPoints` があるか。 |
| `409` | 同じ `playId` に前回と違うスコアを送っていないか。プレイごとに新しいIDを作り、再試行時だけ同じIDを使う。 |
| `422` | ctfの引き分け枚数がまだ未設定。運営の確認後にadminで設定する。 |
| QRが出ない | `coins` が0でないか、API応答エラーがないか、結果画面に `qrImageDataUrl` を表示する処理があるか。 |
| ローカルでは動くが公開サイトで動かない | 本番ホスティング先にも2つの環境変数を登録したか、設定後に再起動・再デプロイしたか、サーバー側APIルートも公開されているか。 |

## セキュリティとスコアの注意

ctfの得点はNodeサーバーで管理されています。ゲームサーバーで本人と相手の得点を参照してAPIへ送ります。クライアントから届いた勝敗や得点をそのまま信用しないでください。

hanbaiとlocketは、現在のコードでは結果をブラウザ内で計算します。サーバーを追加しても、ブラウザから届いたスコアをそのまま転送するだけでは偽の高得点を完全には防げません。公開Webで運用する場合は、ゲームの計算をサーバー側へ移すか、スタッフが結果を確認する仕組みが必要です。管理された会場端末で運用する場合も、この制限を運営と共有してください。

引き分け時のctf付与数は運営が先方へ確認中です。回答があるまでは空欄のままにし、引き分けのQRが出ない状態で運用してください。
