# ORBIS FRONTIER — 火星への15分

既存の宇宙テーマを活かした、日本語の2人用リアルタイム経営ゲームです。15分以内に火星へ**出発した累計人数**で競います。既存の6ラウンド版は `legacy/` に保存しました。

## 起動

Node.js 22以上を使用します。ゲーム本体は外部パッケージ不要です。

```sh
npm start
```

http://localhost:3000 を開き、会社名を入力してルームを作成します。もう一方のブラウザで同じURLを開き、6桁のコードで参加してください。両社が「準備完了」を押すと15分の時計が動きます。1人モード・AI対戦はありません。

HTMLを直接開いたり、静的ファイル用Live Serverで起動したりせず、上記サーバーを使ってください。

### 2台の実端末

1. サーバー役のPCで `npm start` を実行します。
2. 2台を同じ信頼できるLAN / Wi-Fiへ接続します。
3. サーバーPCのLAN IPv4アドレスをOSのネットワーク設定で確認します（例 `192.168.1.20`）。
4. 両端末のChromeで `http://192.168.1.20:3000` を開きます。
5. ルーム作成 → コードで参加 → 両社準備完了。

OSファイアウォールでNode.jsのLAN受信を許可してください。Wi-Fiの端末間通信制限がある場合は展示用ルーターや有線LANを使用します。インターネット接続、生成AI API、フォント配信、外部サービスの契約は不要です。インターネットへの公開運用は想定していません。

ローカル検証では、独立した2つのタブをそれぞれ最初の画面から開いてください。「タブを複製」はブラウザによってセッションがコピーされるため、別プレイヤーとしての検証には使わないでください。

## 遊び方

- 資材工場1つ・資材30個・¥18,000で対称に開始。工場は周期ごとの生産費で稼働します。
- 建設タブで施設を選び、自社区画をクリック。区画番号の選択でも建設できます。
- 滞在施設で移住希望者を集め、宇宙港を建設します。資材は建設用に残すか、市場で売るか選べます。
- 輸送船は宇宙港完成後、¥3,000・資材35個・部品30個で建造。部品・燃料は工場がなくても市場で購入できます。
- 燃料15個・¥350・1人以上で出発準備。準備14秒→カウントダウン6秒→出発→帰還35秒→整備15秒。定員30人、定員未満の運航も可能です。
- 運航報酬はゼロ。資材などの商品販売で次便を支えます。自動運航は、1人以上と必要費用がそろうと開始します。OFFでも進行中の便は完了します。
- 工場は資金不足・在庫上限で停止し、条件が戻れば次の生産周期に再開。手動停止も可能です。滞在施設は60人×レベル、応募は会社ごとに5秒に1人で、施設を増やしても応募速度は増えません。
- 残り2市場は調査後に需要・価格・参入費が判明。物流拠点完成と参入費の支払いで取引可能です。各社別に開放し、市場の在庫・価格は共有します。
- 結果画面に人数・勝敗・商品売上・費用内訳・累計収支・商品別生産数量・便数・平均搭乗人数を表示します。終了後は「経営実績」から結果を再表示できます。両社が再戦に同意すると初期状態に戻ります。

初回出発の調整目標は5〜6分です。自動テストでは開始326秒で初回出発し、さらに2便目まで運航できる経路を検証しています。これは人間2人の試遊によるバランス保証ではありません。

## 共通サーバーと再接続

Node.js標準HTTPサーバーが時計・資金・在庫・価格・生産・建設・運航・得点を管理します。ブラウザは600msごとに状態を取得し、操作をHTTP POSTで送ります。WebSocketを使わないため依存追加が不要で、展示LANでの実装・運用が単純です。操作応答でも最新状態を反映します。

- サーバーの単調時計を使用。ブラウザがバックグラウンドでも進行します。イベントループ遅延時も最大0.25秒の刻みで追いつきます。
- 同時操作はサーバーで直列適用。操作IDによる重複排除を行い、通信再送で二重購入・二重出発を起こしません。再戦時は試合世代番号で古い操作を拒否します。
- セッション用のランダムトークンを `sessionStorage` に保存。同じタブの再読み込みや一時的な通信断から復帰できます。別PCへの移動・閉じたタブの復帰は未対応です。
- 相手の現金・在庫・未公開調査は試合中のレスポンスに含めません。公開施設、便の状態・搭乗人数・発射予定は表示します。試合終了後は両社の財務を公開します。
- 3人目の参加は拒否します。観戦モードは未実装です。
- **サーバー再起動時の試合復元は未実装**です。サーバーはメモリのみで管理し、再起動すると全ルームが失われます。展示中はPCをスリープさせないでください。

### 運営操作

`http://localhost:3000/admin` に運営画面があります。起動ターミナルに表示された運営キーと対象ルームコードが必要です。キーはプレイヤーの状態や画面に配信しません。

- 一時停止 / 再開：両社を同時に停止。通常の一時切断では停止しません。
- 試合初期化：確認後、両社を初期状態へ戻します。

運営キーを固定したい場合は環境変数 `ADMIN_KEY`、ポート変更には `PORT` を設定します。初期化・停止はサーバーでキーを検証します。

## 経済ルール・簡略化

全調整の中心は `config.js`、価格処理は `economy.js`、ゲーム進行は `simulation.js` です。金額単位はゲーム内円、商品の単位は個です。

市場の商品在庫を `S`、目標在庫を `T`、商品基準価格を `B`、市場係数を `F` とします。

```text
S5 = floor(S / 5) × 5
基準価格 = round(B × F × clamp(1 + 0.8 × (1 − S5/T), 0.45, 2.2), 2桁)
購入価格 = 基準価格 × 1.08
販売価格 = 基準価格 × 0.92
輸送費 = 個数 × 市場ごとの輸送費
```

5個刻みの価格段階で、NPCの小さな在庫変化による常時の再確認を抑えています。在庫が減ると段階的に上昇します。大量売買は1個ずつ仮想在庫を動かして積算し、商品総額を整数円に丸めます。見積もりは8秒有効で、サーバーで再計算した総額が変わった場合や在庫不足なら拒否し、再見積もりで確認します。同じ市場を即時往復しても、売買差と輸送費で利益は出ません。

- 市場在庫：0〜260個。会社在庫：商品別400個。1注文：1〜80個。
- 市場の買い取り枠：最大90個、1.5個/秒回復。商品間で共有し、買い取り金額を無制限に現金化できないよう制限します。
- NPC消費：`基礎消費速度 / max(0.5, 基準価格/(B×F))`。高値では消費が減ります。
- NPC供給：中央1.0個/秒、沿岸0.85個/秒、高地0.7個/秒を商品ごとに有限補充。
- NPCの供給品は地区外からの輸入、資金源は地区外企業の予算として扱う簡略化です。NPC企業の貸借対照表や資金残高は実装せず、取引枠を制約にしています。現実経済の完全再現ではありません。
- 売上は商品販売の総額。販売輸送費、購入総額、生産費、運航費、設備投資・参入費、調査費は費用に記録します。初期資金を売上に含めず、設備投資込みの「累計収支」を会計上の利益と呼びません。
- 出発時刻が900秒**未満**の場合だけ人数と便数を一度加算。900秒ちょうど・以降は得点に含めません。燃料・費用・人員は搭乗準備時に一度だけ確保します。

## 検証

```sh
npm test
# ローカルポートを開ける環境で通信テストも実行
NETWORK_TEST=1 npm test
```

ブラウザ検証は追加のPlaywrightとChrome/Chromiumがある場合に実行できます。ゲームの実行時依存ではありません。

```sh
# 別ターミナルで npm start 済みの状態
# PlaywrightモジュールのパスとChrome実行ファイルを任意指定
PLAYWRIGHT_MODULE=/path/to/playwright CHROME_PATH=/path/to/chrome node test/browser.cjs
```

既にプロジェクトから `playwright` を解決できる場合は `PLAYWRIGHT_MODULE` を省略できます。ブラウザがPlaywright標準の場所にある場合は `CHROME_PATH` も省略できます。検証はルームを新規作成し、画像を `test/setup.png`・`test/city.png`・`test/rocket.png` に保存します。

確認済み：
- ロジックテスト12件：価格上下限、往復取引、在庫・需要・取引枠、費用記録、停止と復帰、調査・参入、個人情報の非公開、反復運航、終了境界、初期状態からの縦通し、再戦。
- 通信テスト1件：独立セッション、同時注文、同じ操作の8重再送、3人目拒否、権限検証、一時停止、初期化、古い世代の操作拒否。
- Chromeの独立した2セッション：同時開始、建設反映、販売成立、共通市場、再読み込み、切断表示と再接続、同じ残り時間。JavaScript実行エラーなし。
- 実際のスクリーンショットで開始・街・輸送画面を確認。
